# 论文管理面板 (Paper Manager)

本地可视化管理学术论文的 Web 工具。提供论文浏览、筛选、编辑、元数据自动补全、PDF 关联和新论文提取功能。

## 快速开始

```bash
# 安装依赖
npm install

# 启动管理面板
npm run manage

# 指定端口 (默认 8002)
node scripts/paper-manager.js --port 9000
```

浏览器访问 `http://localhost:8002` 即可。

## 功能概览

### 论文浏览与筛选

- 三栏布局：左侧筛选栏、中间论文列表、右侧详情编辑
- 多维度联合筛选：类型（期刊/会议）、年份、主题、数据完整度
- 筛选标签上的计数随当前筛选条件动态变化
- 全文搜索（标题、作者、venue）
- 缺失字段高亮提示（缺 URL / PDF / 摘要的论文一目了然）

### 论文编辑与保存

- 所有字段可直接编辑：标题、作者、venue、年份、URL、PDF、主题、摘要
- 作者格式：缩写 + HTML 高亮，本人用 `<strong>J. Yang</strong>`，通讯作者加 `*`
- 主题标签：弹出菜单选择（脑机接口 BCI / 神经解码 Decoding / 神经调控 Neuromodulation / 类脑计算 Neuromorphic / 其他 Other）
- 保存直接写回 JSON 文件，无需额外操作
- 支持 PDF 文件重命名（根据标题自动生成规范文件名）

### 从 URL 添加论文（推荐）

1. 点击顶部「＋ URL 添加论文」。
2. 粘贴新论文的完整 URL 或 DOI；停顿后自动获取，也可以按 Enter。
3. 系统按来源可用性补齐标题、作者、期刊/会议、年份、类型、摘要与外部 PDF 链接，并给出主题建议。
4. 检查来源与缺失提示，核实通讯作者、类型、主题等内容后点击「保存为新论文」。
5. 保存只更新本地网站 JSON；预览、检查及发布仍走现有网站流程，不会自动发布。

机制：已知 DOI 先查 Crossref，再从论文页面补缺；仍有缺失时尝试 OpenAlex（按 DOI 或精确落地页匹配，不拿近似标题结果冒充同一篇论文）。支持内容在前的 citation meta 标签、JSON-LD graph 和 arXiv 摘要。Crossref 返回成功但缺摘要时不会提前结束。

- DOI/规范 URL 查重，重复条目提供“打开已有论文”入口，保存接口也会拒绝重复新增。
- 缺失年份和类型不会偷偷使用当前年或默认期刊；必须确认后才能保存。新年份会创建并注册对应年份文件。
- 主题和重点刊会是建议，不是出版社提供的事实；通讯作者、共同一作、奖项、英文别名不自动猜测。
- 来源能提供 PDF 链接时填入外部链接，**并未自动下载本地 PDF**。
- arXiv 的预印本年份不能当作最终发表年份；未取得正式刊会时保持缺失提示。
- 现有论文详情中的「从 URL 自动补全字段」也使用新的抓取模块；切换论文或改动 URL 后，过期结果不会填到当前表单。

#### IEEE 链接的现实限制

IEEE 页面可能返回反爬响应，单靠普通网页请求无法保证成功。系统支持可选的官方元数据接口，使用进程环境变量 **IEEE_API_KEY**；请在本地终端配置，不要将密钥提交到 Git 或粘贴到论文数据中。配置后从同一终端重新启动管理面板。没有 Key 时仍尝试公开页面和精确 OpenAlex 匹配，失败则明确提示，可改用 DOI 链接重试。获取 API Key 和权限需要用户自行申请；本轮没有创建账户或配置真实密钥。

OpenAlex 如需账号额度，也可通过进程环境变量 **OPENALEX_API_KEY** 提供；未配置时尝试公开访问，限流/拒绝会作为来源失败显示，不会编造结果。外部服务的可用性和收录时效无法保证。

管理服务默认只监听 127.0.0.1，并验证 Host/Origin，拒绝任意网站跨域调用管理接口。抓取模块会校验 HTTP(S) 协议、DNS 地址与重定向，拒绝本机/内网目标，并限制超时、重定向次数和响应大小。它不解决整个旧管理服务器其余接口的历史安全问题。

### PDF 关联管理

- 详情页点击「从文件夹选择 PDF」按钮，列出 `papers/` 目录所有 PDF
- 每个 PDF 标注状态：当前关联 / 已关联其他论文 / 可用
- 支持文件名搜索，点击即关联

### 未引用 PDF 智能处理

顶部提示条自动扫描 `papers/` 目录中未被数据库引用的 PDF：

- **可能匹配已有论文**（绿色标签）：标题模糊匹配度 ≥ 40%，显示匹配论文和匹配度
  - 点击后可选：关联到此论文 / 查看论文详情 / 作为新论文提取
- **可能是新论文**（橙色标签）：无匹配，点击后自动提取 PDF 内容
  - 从 PDF 元数据提取标题、作者、摘要、DOI
  - 从文件名解析年份和 venue
  - 预填新论文表单，醒目标注「⚠ 待审核」
  - 确认后保存到对应年份文件

## 数据结构

### 年份文件格式 (如 2026.json)

```json
{
  "journals": [
    {
      "year": 2026,
      "items": [
        {
          "authors": "W. Zou, <strong>J. Yang*</strong>, M. Sawan*",
          "title": "论文标题",
          "venue": "期刊或会议名称",
          "venueHighlight": false,
          "url": "https://...",
          "pdf": "papers/filename.pdf",
          "topics": ["bci", "neuromorphic"],
          "abstract": "论文摘要..."
        }
      ]
    }
  ],
  "conferences": [
    {
      "year": 2026,
      "items": [...]
    }
  ]
}
```

### 论文 ID 格式

`{年份}/{section}/{索引}`，如 `2026/journals/0`，用于唯一定位一篇论文。

## API 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/papers` | 获取所有论文 + 筛选配置 + 未引用 PDF 列表 |
| POST | `/api/paper` | 更新论文（按 ID） |
| POST | `/api/paper/create` | 创建新论文 |
| DELETE | `/api/paper/{id}` | 删除论文 |
| POST | `/api/fetch-url` | 从 URL 抓取论文元数据（Crossref API 优先） |
| GET | `/api/list-pdfs` | 列出 papers/ 目录所有 PDF |
| POST | `/api/extract-pdf` | 从 PDF 提取元数据（标题/作者/摘要/DOI） |

## 技术栈

- 后端：Node.js 原生 HTTP 服务器，无框架依赖
- 前端：原生 HTML/CSS/JavaScript，单文件
- PDF 解析：pdf-parse
- 元数据源：Crossref API、HTML meta tags 解析
- 数据存储：JSON 文件，按年份分文件

## 注意事项

- IEEE Xplore 有 WAF 反爬，直接抓取可能失败。建议用 DOI 链接（`https://doi.org/...`）补全
- 作者名在 Crossref 中是全名，系统自动转为缩写格式
- 保存操作直接修改 JSON 文件，建议定期 git commit
- PDF 文件较大时不纳入 git，建议用 .gitignore 排除 `papers/` 目录

## 当前作者列表一键格式化

已有论文编辑、URL/PDF 新增表单和 URL 抓取结果预览中，作者框旁均有「✦ 格式化作者」。它处理整条作者列表，而非仅处理 J. Yang：例如 Wei Zou → W. Zou，Mohamad Sawan* → M. Sawan*，Chi-Ying Tsui → C-Y. Tsui；作者顺序不变，已有星号保留、不自行添加通讯身份，J. Yang 额外加粗。支持常见全名、姓名倒序、紧凑缩写、连字符名和逗号/分号/换行分隔。无法确定的特殊姓名请人工复核。

按钮调用只读的 POST /api/format-authors，返回结果只填入当前输入框，并显示格式化预览；仍需手动保存才会写入论文 JSON。顶部「批量格式化作者」则仍然是另一项修改全部已保存论文的操作，不要混淆。

## 通过 Chrome 直接保存 PDF（v1.2.0，2026-09-17）

顶部「Chrome 下载助手」负责安装/配对；论文详情中的「通过 Chrome 下载并关联」负责发起任务。Chrome 获取 PDF 内容后，直接传给本机服务，后台核验并按 年份_刊会缩写_标题.pdf 保存到网站 papers/，自动更新 PDF 关联。不再要求用户选择 Chrome 下载位置，不弹另存为，不自动发布网站。

已经安装 v1.0 / v1.1 的用户只需在 Chrome 扩展管理页重新加载同一扩展，再点击助手的“立即检查任务”，无需重新配对。管理面板会提示旧版状态，避免继续产生旧的另存为任务。详细安装及使用说明见 scripts/chrome-paper-helper/README.md。

v1.2 已去除 IEEE 专用限制：尝试出版社/预印本/OA 页面提供的 PDF 元数据、全文链接和查看页；覆盖常见 Frontiers、MDPI、arXiv、Nature、Springer、Wiley、ScienceDirect、OpenReview 等路由，但不保证所有论文都能下载。首次访问新的出版社或 PDF 文件站点，需要用户在 Chrome 助手弹窗点击“允许所需访问并继续”，只申请当前需要的具体来源。DOI 跳转地址被 Chrome 隐藏时，可能申请可选 tabs 权限；权限本身范围较广，代码只读取本次任务创建的标签页，用户也可拒绝并改用出版社最终 URL。403/429、登录、验证码或付费限制会暂停，不自动反复请求或绕过。

公开链接实测已取得 Frontiers（10.3389/fnins.2024.1340164，13 页）和 arXiv（2411.16806，7 页）的有效 PDF，仅暂存私有测试目录，未修改网站数据。这不是新版 Chrome 扩展的实机端到端验证；后者仍需重新加载扩展并由用户授权。

旧版已经下载到默认下载文件夹、但因路径不符而失败的任务，可以点击“恢复归档旧版已下载文件”。只处理当前任务匹配的文件，不扫描任意目录；原文件保留。配对状态仍只在被 Git/发布包排除的 .codex_tmp 内。

## PDF 摘要边界修复（2026-09-15）

摘要提取现在只把独立的 Introduction 章节标题、Keywords/Index Terms（包括 IndexTerms 连写）等结构性标记作为结束边界，不会遇到句子中的 introduction 就截断。明确找到边界的摘要不再被固定截成 3000 字符；科学正文中的 foundation、university 等词也不再被直接当作单位信息删除。

对 IEEE 文本流中夹在左右栏摘要之间的收稿/单位脚注块，按收稿信息到 Digital Object Identifier 的结构剔除；页脚版权/下载提示不会直接切断摘要。对于无法确定边界、退回启发式提取或末尾疑似不完整的结果，会返回并在表单中显示核对提示。扫描版 PDF、异常文本顺序等仍可能需要人工核对。

用户示例 Neuromorphic Computing Chips: Challenges and Trends 的提取结果从 618 字符修复为 1321 字符（174 个英文词），保留完整后半段，结束于 performance and scalability.。已对本地 36 份 PDF 做只读扫描，没有解析失败或丢失已有非空提取结果；这不代表对全部摘要逐一完成了人工准确性核对，也没有批量写回现有摘要。

## Scholar 新论文检查与待录入（2026-09-16）

顶部新增「检查我的新论文」和「待录入论文」。使用 data/profile.json 中的 contact.googleScholar，不按同名作者搜索，不需要 IEEE API Key，也不登录/读取 Google Cookie。

### 检查与频率

- 启动时检查是否到期；服务运行期间每 24 小时最多进行一次自动检查。重启不会重置冷却时间。电脑/服务关闭时不执行，也不是独立的 Windows 或 Codex 定时任务。
- 手动检查至少间隔 15 分钟；按钮在冷却期内只返回缓存状态，不重复请求上游。
- 每次先检查 Scholar 的 robots.txt，只读取配置作者按发表时间排序的一页近期列表，最多 100 条。不抓取 cstart 分页、搜索结果页或论文详情页。
- 限流、拒绝访问、验证码/登录跳转、网络失败、页面结构不匹配时停止检查，至少等待 24 小时；Retry-After 更长时等待更久。不切换代理、账号或浏览器绕过限制。
- 可在候选窗口关闭自动检查。不会注册系统级后台任务，关闭服务后自动检查即停止。

### 查重与审核

按 DOI/规范链接优先匹配网站记录；按用户偏好，完整标题经排版规范化后相同，就直接归为“网站已有”，不再因年份、作者缩写或刊会/预印本写法不同而进入待录入。标题被截断、含乱码或仍有实质差异时，才保留疑似重复提示。不覆盖、合并或删除任何网站论文。

待录入、网站已有、已忽略可以分别查看。忽略只改变本机候选状态，可恢复；候选从 Scholar 第一页消失也不会删除历史候选，更不会删除网站论文。首次在工具中发现不等于刚刚发表。

「自动补全并审核」会查询 Crossref DOI：标题、作者、年份能唯一匹配时转入既有 URL 补全表单；不唯一时展示候选供人工选择，查不到则可手动从 Scholar 条目取得出版社 URL。不会自动使用第一条搜索结果，也不会自动访问 Scholar 详情。进入表单前会保护未保存草稿，最终仍需人工点击保存。PDF 下载与网站发布保持现有流程，不由 Scholar 检查直接触发。

### 状态与数据安全

界面区分最近尝试、最近成功、下一次检查及失败原因。失败不会显示成“没有新论文”，上次成功候选仍保留。候选/设置/冷却记录保存在 .codex_tmp/scholar-watch.json，不进入 Git 或公开发布包；网站论文 JSON 不因检查而修改。

目前不读取 Scholar 通知邮件、不申请额外浏览器权限、不依赖 Chrome 下载助手。邮箱通知接入属于以后可选的独立功能。

### 本轮验证范围

已用隔离数据验证页面解析、访问规则、查重、冷却、429/Retry-After、失败保留、候选忽略恢复、DOI 选择、草稿保护、真实本地 HTTP 入口和浏览器候选界面。2026-09-16 首次后台实际请求发生网络失败，未取得真实 Scholar 列表；系统已记录失败及下次检查时间，不能据此断言没有新论文。随后用户开启代理，已接通 Windows 系统 HTTP(S) 代理并于 2026-09-16 成功读取真实主页的 100 条近期记录：80 条匹配网站已有条目，12 条未匹配，8 条疑似重复；后两类进入待核对，不自动写入网站。

### Scholar 的代理与网络恢复重试

Scholar/Crossref 发现客户端会优先使用进程中的 SCHOLAR_HTTPS_PROXY 或 HTTPS_PROXY；未配置时，在 Windows 上只读当前用户已开启的系统 HTTP(S) 代理。该代理仅用于发现客户端，不修改 Windows 设置、全局 fetch、IEEE API Key 请求或本地管理接口。不执行 PAC 脚本，也不自动更换节点。原生代理 Agent 需要 Node 24.5+（或受支持的 Node 22.21+），当前本机为 Node 24.20。

用户确认网络恢复后，可以针对“网络失败”做一次显式重试；这种重试仍至少间隔 15 分钟，不能越过 403/429、人工验证或访问规则禁止的冷却期。界面在允许时显示“网络恢复后重试”。正常自动检查仍遵守每日频率。

### 标题优先去重（2026-09-16）

同标题自动归为网站已有，并从默认待录入列表排除；仍可在“网站已有”分类查看。规范化忽略大小写、标点、空白、首部冠词、toward/towards 写法、数字后的 μ/µ/u 等价微单位，以及明确 ISSCC 刊会中的报告编号。不会忽略不同数值、Part I/II 等实质标题差异；省略号/乱码不按完整标题认定。此宽松规则只用于网站查重，不放宽 Crossref DOI 选择规则。缓存记录会立即重新分类，无需重新访问 Scholar。

### Scholar 数学符号与字符集修复（2026-09-16）

部分 Scholar 标题把 μ、上标 ² 等画成带 aria-label 的 SVG，而不是普通文本。现在从可访问标签恢复这些数学符号，再进行标题查重；未知公式保留提示，不把 W 与 μW 或不同数值粗暴等同。A 510μW 0.738-mm²… 这条记录此前因 SVG 被当作 HTML 标签移除而漏判，已补回原有符号。旧缓存可根据同一次成功检查的本地 HTML 快照重解析标题，不增加 Scholar 请求，也保留用户的忽略状态。

读取新的网络响应时，按 HTTP/HTML 声明的字符集解码（包括 ISO-8859-1），避免一律按 UTF-8 产生替换字符。已经不可逆损坏的旧字符不会凭空猜测，等待下一次成功读取刷新。

# 首页分享信息

## 范围与维护

- 仅覆盖中文首页和英文首页；没有修改其他页面的分享信息。
- 元数据直接输出在 HTML head 中，不依赖 JavaScript 执行。
- 分享文案、HTTPS URL、图片及尺寸统一维护于 `scripts/share-metadata.js`。
- 中文首页通过 `scripts/build-zh-pages.js` 引用同一模块，避免重新构建时丢失。
- 英文首页通过带标记的区块更新。运行 `npm run build:share` 同步两种语言；运行 `npm run check:share` 验证。
- 继续保留原有 SEO title、description 与 Person 结构化数据；分享文案独立维护。
- 当前使用网站已有个人照片 `static/assets/img/yangjie.jpg`（273 × 339，JPEG），未新增或公开私人图片；图片已在现有发布白名单覆盖范围内。
- 本版没有增加公众号、AppID、签名服务、微信 SDK 或额外追踪脚本。没有用隐藏图片干扰页面内容。

## 2026-10-15：无 SDK 的静态兼容性试验

- 用户希望保留照片，并改善微信分享卡片左下方的留白；只修改网站代码，不接入 SDK 或后端服务。
- 在中英文首页 head 上声明 WebPage 微数据作用域，补充 itemprop=name、description、image，分别复用现有 OG 标题、短摘要和照片 URL。不新增图片，不修改原有 SEO title、meta description、Person JSON-LD 或正文布局。
- 这是标准元数据兼容性试验，不是已验证的微信修复。没有官方证据保证微信采用这些字段，也不能通过元数据控制卡片模板、强制展示摘要或恢复网址。
- 用户提供的旧卡片显示 http:// 地址、新卡片显示照片；旧卡片的网址不是网站摘要。两个样本不能证明图片标签导致网址消失，也不能证明缓存、协议或客户端版本相同。
- 本地检查覆盖作用域、字段一致性、唯一性、HTML 转义及重复构建稳定性。微信实际表现仍未验证。

### 这版如何实测（仅在用户明确授权发布之后）

1. 先确认线上原始 HTML 已包含这版 itemprop 标签；本地改动不会影响当前线上卡片。
2. 使用同一设备、同一微信版本和同一个分享入口，打开正式 HTTPS 首页，重新分享给文件传输助手，不转发旧卡片。
3. 如仍无变化，再尝试 https://yangjie.ac.cn/?share_probe=20261015-microdata，并记录标题、摘要、头像及截图。该参数只用于诊断，不保证绕过微信缓存；canonical 和 og:url 不改。
4. 对比正式地址与诊断地址的结果。若仍为空白，记录为本试验未改善，不继续叠加未经验证的标签，不自动引入 SDK。
5. 回退时仅移除本次新增的 WebPage 作用域和三个 itemprop 字段，并同步生成器、测试和文档；保留原来有效的 OG/Twitter 标签及照片。

## 验证边界

本地测试只能证明 HTML 中的分享声明完整、图片存在、URL 与图片尺寸一致；不能证明微信客户端已经采用这些字段。也不能仅凭缺少缩略图，认定原因一定是缺少 Open Graph 标签。

本地构建不会部署。只有用户明确授权并完成发布审核后，才能通过既有发布流程将这些改动同步到线上；不要为验证本功能直接运行发布脚本。部署记录保存在本地发布回执中，线上部署成功也不等于微信缩略图已经通过人工实测。

## 用户授权发布后的人工验收

1. 核对线上 HTTPS 首页原始响应中的分享标签，而不仅是浏览器执行脚本后的 DOM。
2. 核对声明的图片 URL 可以匿名访问，返回真实 JPEG 及正确 Content-Type；检查跳转、访问限制和防盗链。
3. 在电脑微信中重新打开 HTTPS 首页，重新生成分享消息，不只转发先前的旧卡片。记录具体客户端版本、操作入口和截图。
4. 在手机微信中重复同样的分享流程，分别记录标题、简介、缩略图；不要把不同客户端或入口的结果混为一谈。
5. 单独测试英文首页，确认文案、URL 与语言正确。
6. 若结果不变，可用一次性诊断查询参数尝试区分旧链接缓存影响，但不能把参数变化视为清除微信缓存的保证。`canonical` 与 `og:url` 仍保留正式地址。
7. 若仍无缩略图，先收集请求/访问与客户端证据，再核对微信官方文档、账号资质和 SDK 适用入口；不要直接承诺申请账号或添加 SDK 就能解决桌面端转发问题。

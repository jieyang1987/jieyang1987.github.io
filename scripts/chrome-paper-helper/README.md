# Chrome 论文 PDF 直存助手（v1.2.0）

更新日期：2026-09-17。

## 已安装旧版：重新加载，不必重新配对

在 Chrome 打开 `chrome://extensions`，找到“网站论文 PDF 下载助手”，点击重新加载。继续使用同一 Chrome 用户配置和同一扩展目录，不需要重新配对。再打开助手弹窗点击“立即检查任务”，让管理系统识别到 v1.2.0。未升级的助手不能领取非 IEEE 任务。

v1.2 去除了 IEEE 专用限制，尝试识别出版社、预印本和开放获取论文页面实际提供的 PDF 链接，包括 citation_pdf_url 元数据、PDF alternate 链接、PDF 查看页、嵌入文件及标明 PDF/全文下载的入口。常见路由覆盖 IEEE、Frontiers、MDPI、arXiv、Nature、Springer、Wiley、ScienceDirect、OpenReview；这不是对每个网站或每篇论文可下载性的保证。

沿用 v1.1 的直存方式：**Chrome 获取 PDF 内容，通过已配对的本机接口传给网站后台；后台核验、命名并直接写入 papers/**。新流程不调用 Chrome 下载/另存为接口，不需要设置固定的 Chrome 下载位置。

## 首次安装

1. 使用能正常访问目标论文的 Chrome 用户配置；开放获取论文通常不需要登录。
2. 打开 `chrome://extensions`，开启开发者模式，加载本目录中的已解压扩展（应能看到 manifest.json）。安装和权限由用户自行确认；不要绕过企业浏览器策略。
3. 在本机论文管理面板点击顶部“Chrome 下载助手”。窗口显示网站 PDF 的最终保存目录，只读，无需选择下载位置。
4. 生成一次性配对码，将管理地址和配对码填入 Chrome 工具栏的助手弹窗，点击连接。配对码不是 IEEE API Key。

配对凭据仅保存在 Chrome 扩展本地存储和被 Git/发布包排除的 .codex_tmp/chrome-download-bridge.json。不会读取或导出 Cookie，也不需要向工具提供网站密码。扩展使用浏览器请求携带已有会话，而不是自行复制登录凭据。

## 首次访问新站点时授权

- 本地管理接口、IEEE Xplore 和 doi.org 保留原有站点权限。其他站点按当前任务需要，在助手弹窗中显示具体地址。
- 点击 **“允许所需访问并继续”**，由 Chrome 显示并确认授权；后台不会自动批准。虽然清单允许申请 HTTPS 站点权限，实际每次只申请任务需要的具体来源，不申请一次性访问全部网站。
- 论文跳转到另一个出版社或 PDF CDN 时，可能需要再次确认该来源。自动跟随重定向可能已触达目标站点，但助手会在读取 PDF 正文前检查目标来源权限；没有权限时取消读取并暂停。
- DOI 跳转后，如果 Chrome 隐藏未授权站点的标签页地址，助手可能额外申请可选的 **tabs（标签页地址读取）权限**。此权限本身范围较广；当前代码只按 ID 读取自己为任务创建的标签页，不枚举或读取其他标签页。可以拒绝，在管理系统取消该任务，改用出版社最终页面 URL 发起新任务。
- 拒绝权限不会被当作成功，也不会继续下载。可以稍后授权或在管理系统取消任务。

## 日常流程

先保存论文标题和 URL，再点击详情中的“通过 Chrome 下载并关联”。

1. 尝试已保存的外部 PDF 地址，或打开论文 URL，识别页面实际提供的 PDF 链接。
2. 新站点需要授权时暂停；授权后使用 Chrome 的正常会话获取 PDF 字节，不弹出保存窗口。
3. 普通 PDF 查看页可继续解析；失效链接可尝试同页其他 PDF 入口，候选次数和查看页跳转均有限制，不会无限尝试。
4. 将 PDF 内容传给已配对的本机服务；只有本机配对凭据有效的请求才能提交。
5. 后端核验文件头、结束标记和可解析性；文件不得超过 100 MB。检查已知来源标识和 DOI；若 PDF 能识别出唯一 DOI，也会与当前论文比较。无法从所有 PDF 可靠识别论文身份，归档后仍建议核对。
6. 根据论文年份、刊会缩写、标题生成文件名，同名加序号，不覆盖已有文件。
7. 直接写入网站 papers/，只更新该论文的 pdf 字段，保留作者、摘要、奖项、英文信息及其他字段。
8. 不自动提交 Git，不自动发布网站。

遇到 HTTP 403/429、登录、验证码或付费限制，助手暂停提示人工处理，不绕过限制，也不自动反复请求。可打开任务页面核对，处理完成后手动点击“立即检查任务”。开放获取不等于任意入口都能直接下载；站点脚本、浏览器会话和网络条件仍可能影响结果。找不到链接时会明确提示失败，不把 HTML 当成 PDF 保存。

## 旧版已下载文件的恢复

管理面板的失败任务下有“恢复归档旧版已下载文件”。它只查找该任务随机 ID 对应的 PDF，接受原 Chrome 下载根目录及 PaperManager 子目录，不扫描或读取任意文件路径；找到唯一文件后核验、命名并关联，保留原件。

对于用户明确指定的其他已下载 PDF，可以在核对论文身份后，通过本机受保护的 PDF 接收接口归档。不能把任何无关文件当成同一论文上传。

## 可靠性与验证范围

- 下载期间排序或编辑作者不会导致下标错位或覆盖作者；身份信息或 PDF 关联变化时停止处理。
- 重复完成请求和提交附近的服务重启可恢复，不重复创建已完成副本。
- JSON 写入失败会回滚本次新增的网站 PDF；对 Windows/Dropbox 短暂文件锁进行有限重试，保持原子替换。
- Chrome 的旧版下载权限仅用于兼容尚未完成的旧任务；新版获取路径不会发起 Chrome Save As 下载。
- 自动测试覆盖非 IEEE 任务、来源校验、权限暂停/恢复、CDN 授权、失效候选回退、HTML 查看页与循环停止、二进制上传、命名关联及旧文件恢复。
- 公开链接实测成功：Frontiers DOI 10.3389/fnins.2024.1340164（13 页）和 arXiv 2411.16806（7 页）。通过现有代理获取并核验，文件只放在 .codex_tmp/oa-pdf-probe，未改网站论文数据，也未自动归档到公开目录。
- 上述公开链接实测不等于真实 Chrome 扩展端到端测试。后者需要用户重新加载扩展并亲自确认新增权限；未完成前不能声称所有 Chrome 流程均已实机验证。

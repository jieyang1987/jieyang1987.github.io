## 结论

适合渐进式重构，不建议为目前 144 篇论文直接重写成大型框架或迁移数据库。继续保留 Node.js、原生前端、分年份 JSON，以及中英文网站读取数据的现有约定。优先解决数据正确性、文件操作安全和异步状态问题，再拆分模块。

本次已通读三个核心文件：后端 paper-manager.js（修复后 1431 行）、前端 paper-manager.html（2887 行）、命令行 add-paper.js（829 行），并检查管理说明、数据配置、网站数据消费入口、测试/发布入口。第三方 node_modules 不在逐行审查范围。

## 尚未修复的问题（按优先级）

### P1：PDF 下载成功接收后可能直接终止服务

位置：paper-manager.js:1105–1118，downloadPdf()。

Buffer.concat() 返回 Buffer，但魔数检查调用了 buf.substring(0, 4)。隔离响应事件测试已复现 TypeError: buf.substring is not a function。异常发生在 res 的 end 回调中，不会自动转成外层 Promise 的 reject，可能作为未捕获异常结束 Node 进程。相邻同步写文件异常也有同类问题。

建议：用 Buffer 的 subarray()/toString() 检查文件头；将事件处理中的错误显式转成 reject；覆盖有效 PDF、非 PDF、断流、超时、磁盘写失败。后续统一网络请求层，并流式写临时文件而非无限制缓存完整响应。

### P1：论文 ID 是数组下标，可能操作错论文

位置：paper-manager.js:46–69、80–171；paper-manager.html:1730–1769、1967–2009。

当前 ID 为“文件年份/类型/数组下标”，不是稳定身份。已用合成数据复现：A、B、C 的列表删除 A 后，旧页面继续用原来 B 的 ID 保存，会覆盖 C。多窗口、后台下载期间排序、其他入口新增论文都可能使下标变化。

同时，ID 不包含分组年份；一个文件出现多个年份分组时会重复。删除、排序又按第一个具有该下标的分组处理，而更新依赖可编辑的 groupYear。已复现修改年份时覆盖另一个年份分组中的条目。当前真实数据尚未发现重复 ID，不能据此认为该设计安全。

建议：给论文引入持久稳定 ID，数组顺序只表示排序；年份迁移用独立操作。首次迁移生成预览、备份并验证中英文页面兼容；为修改请求增加版本/内容哈希检查，拒绝旧页面覆盖新内容。

### P1：本地管理服务的访问和文件边界不足

位置：paper-manager.js:252–274、1196–1216、1315–1322、1392–1399、1419。

默认监听未限定到 loopback，无会话校验且允许任意来源 CORS。若端口可达，调用方可访问写接口。renamePdf() 对旧路径和新文件名直接 path.join，没有验证目标必须位于 papers/。已在临时目录复现：非 PDF 的 outside.txt 可以经接口逻辑被移到 papers/ 之外。提取和预览路径也缺乏统一目录边界校验。并未尝试访问真实项目外文件或进行公网测试。

建议：默认只监听 127.0.0.1；同源/Host/Origin 检查及本地会话令牌；所有本地文件操作统一 resolve + realpath 边界校验，限制普通 PDF 文件并拒绝越界/链接逃逸。对外部抓取 URL 限制协议，检查目标和每次重定向，避免访问内网服务。仅隐藏管理页面或仅改 CORS 不足以替代服务端校验。

### P1：重命名与 JSON 更新不是一个可靠操作

位置：paper-manager.html:2085–2115；paper-manager.js:370–445；add-paper.js:523–576。

单篇重命名先由一个请求改文件，再由前端调用完整保存请求。后一步如果因为空作者、年份校验、网络失败或页面切换而失败，文件已改名，但 JSON 仍指向旧名。

批量流程虽有两阶段临时文件，但回滚不完整：已模拟 JSON 写入失败，结果是 b.pdf 已存在、a.pdf 已消失，JSON 仍引用 a.pdf。因为临时文件已被移走，catch 再从临时路径回滚不能恢复它。批内冲突和部分失败还需要成组校验。

建议：在后端把改文件和更新引用集中为一个服务操作；执行前检查全部输入和引用，记录操作日志/备份、明确提交点，失败时从实际最终路径恢复并报告恢复结果。单个 JSON 使用临时文件替换，跨文件操作仍需额外恢复机制，不能把一次 rename 当作跨文件事务。

### P2：新年份处理与界面承诺不一致

位置：paper-manager.js:176–214；add-paper.js:418–443；paper-manager.html:2523–2524。

Web 面板遇到配置之外的新年份会回退到第一个年份文件。已复现新增 2027 年论文写入 2026.json；读取时 year 变成 2026，groupYear 才是 2027，并与已有条目产生重复 ID。命令行则能创建并注册新年份文件，两套行为不一致。

建议：将 ensureYearFile 和年份归档策略抽成共享存储服务。区分实际发表年份与存储桶，读取时不要用文件年份冒充论文年份；明确早期论文归档规则。

### P2：接口校验与错误处理分散

位置：paper-manager.js:80–171、176–240、1196–1204。

标题/作者/venue 主要靠前端校验，后端缺少统一字段类型、类型枚举、整数下标范围、URL 和文件规则。已复现 DELETE 的 -1 下标会删除最后一条；无效 JSON 被当成空对象，容易产生误导性错误。请求体没有大小上限，部分读取失败被静默跳过，部分接口 HTTP 200 却返回 ok:false。

建议：共享请求 schema/显式验证函数；严格拒绝非法 ID、负数和无效 section；限制请求/响应大小；结构化错误、统一状态码；损坏 JSON 应显式提示文件，而不是悄悄漏掉论文。

### P2：前端编辑状态与异步请求生命周期混在一起

位置：paper-manager.html:1730–1737、1970–2009、2205–2246、2417–2467、2772–2831。

selectPaper() 直接替换详情 DOM，没有未保存修改提示。URL 补全等待期间可以切换论文，返回后 renderAutoFillPreview() 又查找当前页面的表单，有把 A 的抓取结果呈现在 B 表单中的风险。其他批处理也依赖全局数组和已被替换的 DOM；单篇批量下载成功后不会立即刷新全局数据，全部下载也不跳过已完成项。

建议：维护明确的当前论文 ID、草稿、dirty 状态和异步任务状态；切换时确认丢弃；AbortController/请求序号和 ID 检查阻止过期结果写入；批任务独立于详情 DOM，返回结构化结果而不是通过按钮文字判断成功。这些属于静态控制流审查，尚未做浏览器交互复现。

### P2：HTML 转义与 JavaScript 事件参数转义混用

位置：paper-manager.html:1438–1452、1496–1498、1904–1906、2385–2389。

escapeAttr() 面向 HTML 属性，不会让数据成为安全的内联 JavaScript 字符串。PDF 文件名被放进 onclick="selectPdf('...')" 等表达式；文件名含单引号（例如 O'Brien.pdf）就会破坏表达式，还有注入风险。使用实际 escapeAttr() 生成事件表达式后进行语法编译，已复现 SyntaxError。单纯把单引号改成 HTML 实体仍不能解决事件处理器的解析上下文问题。

建议：删除动态拼接的内联 onclick，使用 data-* + addEventListener/事件委托，普通文本用 textContent；链接另做协议白名单。

### P2/P3：业务规则重复、界面说明与实际能力漂移

- DOI 提取函数在后端重复；venue 映射和文件名清洗在前端、CLI 多处维护。
- 后端作者格式化会自动给 J. Yang 添加通讯星号；CLI 高亮逻辑则保留有无星号。姓名高亮不应隐式推断通讯身份，需明确用户规则后统一。
- /api/download-pdf-check 只依据 DOI/可推断 URL 标记候选，没有实际查询 OA 状态；前端却写“可下载（开放获取）/需订阅”。应改为“待尝试/未找到自动下载线索”，或者真正执行检查后再分类。
- README 的 PDF 选择器说明称会显示全部关联状态，代码却隐藏已被其他论文关联的 PDF。
- CLI 结束提示仍引导手工 tcb hosting deploy，与 DEPLOYMENT.md 的统一发布流程不一致。
- 前端近千行 CSS 与业务脚本同文件，固定三栏且无媒体查询；移动端/键盘可用性可在逻辑拆分稳定后改善。

## 推荐的模块边界（建议，尚未实施）

- server：监听配置、路由、访问控制、请求解析和统一错误处理。
- repository：论文身份、年份归档、读写、版本冲突及原子替换。
- paper-service：新增/编辑/移动/删除/关联 PDF 等业务操作。
- pdf-service：提取、命名、下载、重命名和跨文件恢复。
- metadata：Crossref/HTML/OA 适配器，共用受限网络客户端。
- shared：字段验证、作者规则、venue 映射、DOI 和文件名规则。
- ui/api：集中 fetch、超时、错误解析。
- ui/state：列表/筛选、选中项、草稿、任务生命周期。
- ui/views：列表、编辑表单、PDF 选择器、元数据预览和批处理视图。
- ui/styles：从 HTML 中拆出的管理面板专用样式。

CLI 与 Web 应共同调用同一套业务/存储服务，而不是 Web 反向依赖包含整套交互录入流程的 CLI 脚本。模块留在开发工具目录，避免放进当前会自动发布的 static/ 目录；若确需共享公开模块，必须明确发布白名单。

不必先引入 React、Express 或数据库。先用现有技术建立可测试边界，只有未来出现多人并发、全文索引或大规模数据需求，再评估数据库迁移。

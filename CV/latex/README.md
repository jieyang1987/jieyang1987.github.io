# 杨杰 CV：内容与 LaTeX 版式分离

本目录从原 Word 简历迁移而来。现在“个人荣誉”“研究成果荣誉”“邀请报告”以及“期刊论文／会议论文”均接入网站数据的增量同步；书籍章节与其余内容保持独立维护。全部操作仍是本地构建，不包含提交、上传或发布。

## 哪个文件用来做什么

| 文件 | 用途 | 日常是否编辑 |
| --- | --- | --- |
| `content.md` | CV 正文、标题层级、论文条目、强调和链接 | 修改简历内容时编辑 |
| `templates/layout.tex` | 纸张、页边距、字体、字号、缩进、段间距和分页规则 | 修改外观时编辑 |
| `scripts/build.py` | 将 Markdown 内容填入模板，生成独立 LaTeX 文档 | 通常不需要 |
| `scripts/compile_pdf.py` | 使用本地 Tectonic 编译当前 `cv.tex`，不覆盖编辑器中的改动 | 生成 PDF 时运行 |
| `scripts/import_word.py` | 从原 Word 一次性迁移内容 | 不作为日常构建步骤 |
| `scripts/verify_migration.py` | 将首次迁移结果逐段与原 Word 核对 | 仅用于迁移核验 |
| `tests/test_build.py` | 内容解析、特殊字符、链接和生成流程测试 | 修改脚本后运行 |
| `cv.tex` | 自动生成的独立 LaTeX 文档，可在内置编辑器中打开 | 不手改，重建会覆盖 |

原 Word 和原 PDF 设计样张均未改动。当前内容来自 `../简历_杨杰 - 2025-9-15.docx`，不是设计样张 PDF。

## 推荐用法：网站数据增量同步与 PDF 自动生成

在**网站项目根目录**运行：

```powershell
npm run build:cv
```

这个命令会按顺序执行：读取网站当前数据 → 增量合并个人荣誉、研究成果荣誉、邀请报告及两类论文 → 更新现有 `content.md` 和 `cv.tex` → 编译原位置的 `cv.pdf`。不需要再从 Word 导入，也不需要手工复制网页条目。

其他入口：

```powershell
# 同时重建中文网站和 CV；不运行部署。
npm run build:site-and-cv

# 只同步内容、更新 TeX，不编译 PDF。
npm run sync:cv

# 只读检查：源数据、生成 TeX、PDF 是否一致；过期时返回非零退出码。
npm run check:cv

# 本机字体/宏包已缓存时可禁用 TeX 资源下载。
npm run build:cv -- --offline
```

这是**构建时自动同步**，不是后台监听、定时任务或自动发布。保存网站 JSON 本身不会启动进程；运行 `build:cv` 或 `build:site-and-cv` 后才会同步生成。既有 `build:zh` 行为不变，避免在尚未纳入 CV 源码的其他检出环境中意外中断网站构建。

### 网站数据来源

- 个人荣誉：`data/zh-home.json` 的 `selectedHonors`，不把 `paperAwards` 中的成果奖项混进个人荣誉。
- 邀请报告：`data/coverage.json` 的活动记录，经类型筛选；报道、获奖、项目启动、海报、圆桌、专题主席和仅组织 Special Session 的记录不自动当成邀请报告。

这两份网站数据中的现有条目增加了稳定 `id`，**没有改动网页可见的标题、日期或顺序**。后续修改同一条内容时保留它的 `id`，这样改题目/日期不会被误认为新增事件。新记录推荐附一个新的、不重复的 `id`；没有 ID 时脚本会使用日期和会场名称回退匹配，冲突时停止并要求明确标识。

对于文字没有明确说明报告身份的新活动，可补充：

```json
{
  "id": "a-stable-event-id",
  "date": "2026.10.1",
  "title": "某学术活动：报告题目",
  "cv": { "kind": "invited-talk" }
}
```

上面只是字段格式示例，不是实际履历。`cv.include: false` 可排除该活动的新导入；已有 CV 历史记录仍不会被自动删除。未来日期的活动进入待核对，不直接表述为已经完成的报告。

### 增量与保护规则

1. 只修改接入的个人荣誉、研究成果荣誉、邀请报告与两类论文列表；其他内容和已确认的配色/字体不变。
2. 旧 Word/CV 中的网站未收录条目继续保留；网站后来删除条目，也不自动删除 CV 历史。
3. 已知同一事件合并处理，不重复增加；旧 CV 中更完整的地点、题目、补充说明不丢弃。
4. 由网站新增、且没有被手工修改过的 CV 条目，后续会跟随同一个网站 ID 更新。
5. 如果你手改了受管理的 CV 条目，脚本保留你的改动，列入待核对，不悄悄覆盖。
6. 新旧题目/日期冲突或活动性质不明时，保留已有内容，并写入 `SYNC_REVIEW.md` 与 `sync-report.json`。
7. 荣誉按年份倒序、报告按年月日倒序排列；**邀请报告从总条数递减编号至 1**（目前 27→1），以后新增报告会自动更新首号，论文列表编号不受影响。
8. 检测到在编辑器直接修改了生成的 `cv.tex` 时，工作流停止，防止覆盖。先把改动迁回内容或模板，再重新生成。
9. PDF 被阅读器锁定时，命令会报告失败，不把旧 PDF 冒充新版本；关掉 PDF 后重跑即可，重复运行不会重复新增记录。

## 底层生成流程（不自动同步网站）

在本目录打开终端，使用 Python 3.10 或以上版本：

```powershell

```

构建只需要 Python 标准库，不依赖 Word、Pandoc、网络服务或第三方 Python 包，也不会执行提交、上传或部署。

1. 修改 `content.md`。
2. 如需调整排版，修改 `templates/layout.tex`。
3. 运行上述命令，重新生成 `cv.tex`。
4. 在 Codex 的 LaTeX 编辑器中打开 `cv.tex`，查看编译诊断和 PDF 预览。

最终的 `cv.tex` 已内联内容和模板，没有 `\input` 或其他项目文件依赖。虽然日常维护分为多个文件，生成的 `.tex` 可以作为独立文件交给编译器。

模板以 XeLaTeX 为目标。本机优先使用与 Word 一致的宋体、黑体、Times New Roman；缺少这些字体时回退到 Fandol/TeX Gyre，不把系统字体复制进源码仓库。不同电脑使用回退字体时，不保证逐行、逐页相同。保留 A4、19 mm 左右页边距、24.8 mm 上下页边距；正文、研究说明和论文列表分别配置字号与行距。

如果用户已有支持上述字体和宏包的 XeLaTeX 环境，也可以自行编译独立的 `cv.tex`。首次迁移时没有安装编译环境；后经用户于 2026-10-05 明确同意，添加了独立的本地 Tectonic 编译方案，见下文。

## 内容文件的约定

这是面向本份 CV 的小型 Markdown 子集，而不是通用 Markdown 转换器：

- `#`：整份简历标题；`##`：一级栏目；`###`：经历/成果分类；`####`：研究主题或年份。
- 一个空行分隔一个段落。普通段落可以分行书写，构建时合并。
- `**文字**`：加粗；`*文字*`：斜体；`***文字***`：粗斜体。
- `mm²`：数字上标；作者名单中 `**J. Yang**\*` 为通信作者、`**J. Yang**\*#` 为通信作者兼共同第一作者（标准 Markdown 预览显示星号，PDF 会将作者标记排为上标）；`<sub>DD</sub>`：下标；`<u>文字</u>`：原稿下划线。
- `[显示文字](https://...)`：链接，也支持 `http://` 和 `mailto:`。
- `16. 论文文字` / `1、 条目`：显式编号；本次保留 Word 的实际编号，论文列表**不自动重排已有编号**。邀请报告由增量同步流程单独排序并自动编号。
- `- 内容`：普通项目；前面加四个空格为次级项目（保持空格，不用 Tab）。
- `> 内容`：附属说明，如导师或项目经费。此处是缩进约定，不是引用出处。
- `\*`：字面星号，例如通信作者的 `*`；不要误删此转义。
- 不支持表格、图片、脚注、代码块、任意 HTML 或任意 LaTeX 指令。内容中的 LaTeX 特殊字符会转义，不作为命令执行。

基本信息栏目中的冒号用于对齐字段名和值。不要把整行字段名和值放在同一对强调标记中；分别标记，例如 `**姓名:** **杨杰**`。

内容文件保留强调、链接等语义标记，但不含页边距、字号、字体、手工分页等版式配置。这些统一放在模板中。

## 独立本地编译方案

用户已授权使用独立编译器。本机安装的是 Tectonic 0.17.0，官方 Windows x86_64 MSVC 发行版。下载归档的 SHA-256 已与官方 GitHub release API 提供的摘要核对：

```text
f61ce51f0b0ade1015b7de7ef368541c5424e9756ecbd0d7af97d6d48030845f
```

- 安装位置：当前用户的 `%LOCALAPPDATA%/Programs/Tectonic/0.17.0/`，不在网站仓库内。
- 没有修改系统 PATH，没有启用远程编译，没有上传 CV 源文件。
- 首次编译需要联网获取字体、宏包和格式文件；所需资源缓存齐全后，可使用 `--offline` 禁止下载。
- 安全模式 `--untrusted` 始终启用，不允许文档使用已知不安全功能。
- `compile_pdf.py` 只编译现有 `cv.tex`，不会重建它，因此不会覆盖在编辑器中直接做的修改。

在本目录运行：

```powershell
# 只有内容或模板改动后才需要这一步；会覆盖生成文件 cv.tex。
python scripts/build.py

# 编译当前已有的 cv.tex，结果为同目录的 cv.pdf。
python scripts/compile_pdf.py

# 字体/宏包已经缓存后可用此模式，不发起资源下载。
python scripts/compile_pdf.py --offline
```

其他电脑可以用 `--compiler` 指定自己安装的 Tectonic，或设置环境变量 `TECTONIC_BINARY`。脚本也会检查 PATH；不会擅自下载或安装任何软件。

这条路径只解决独立 PDF 生成，并不保证修复 Codex 内置编辑器的自动 PDF 预览。内置编辑器仍保留当前源文件。
